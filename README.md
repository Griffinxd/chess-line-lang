# ChessLineLang (CLL)

## Project Overview
ChessLineLang (CLL) is a domain-specific language designed for chess opening preparation, line analysis, and puzzle description. It provides a formal syntax to define chess positions, execute sequences of moves, and request positional evaluations via Stockfish integration.

## Features
- Custom handwritten lexer tailored for chess notation and language constructs
- Handwritten recursive-descent parser
- Comprehensive Abstract Syntax Tree (AST) generation
- Static type checker with semantic validation
- Tree-walking interpreter with full runtime semantics
- Stockfish engine integration for position evaluation (`eval()`) and best-move queries (`eval.move()`)
- Strict syntax validation with line-level error reporting

## Dependencies

### Python (required)
- **Python 3.10+** — the language runtime
- **[python-chess](https://pypi.org/project/python-chess/)** (`>=1.10.0`) — board representation, move validation, FEN parsing, and Stockfish engine bridge. This is the only external Python package and is installed automatically by the build script.

### Stockfish (optional, for `eval()` / `eval.move()`)
- **[Stockfish](https://stockfishchess.org/)** — open-source chess engine used for position evaluation and best-move computation. The build script can download and install it automatically, or you can install it yourself via a package manager:
  ```bash
  # macOS
  brew install stockfish

  # Ubuntu / Debian
  sudo apt install stockfish

  # Arch Linux
  sudo pacman -S stockfish
  ```
  If Stockfish is not installed, all other CLL features (board manipulation, move execution, printing, etc.) work normally — only `eval()` and `eval.move()` will raise a `MissingEngineError` at runtime.

## Building the Project

The included `build.sh` script automates the full setup:

```bash
chmod +x build.sh
./build.sh
```

This will:
1. Detect Python 3.10+ on your system
2. Create a virtual environment (`.venv/`)
3. Install Python dependencies from `requirements.txt`
4. Download and install the correct Stockfish binary for your OS/architecture into `engines/`
5. Run the full test suite
6. Generate a `./cll` convenience runner script

### Build Options

| Flag           | Effect                                            |
|----------------|---------------------------------------------------|
| `--no-engine`  | Skip Stockfish download (eval features won't work)|
| `--no-tests`   | Skip running the test suite                       |
| `--clean`      | Remove `.venv/` and `engines/` before rebuilding  |
| `-h`, `--help` | Show help message                                 |

```bash
# Build without Stockfish
./build.sh --no-engine

# Clean rebuild
./build.sh --clean

# Build without running tests
./build.sh --no-tests
```

## Running the Project

After building, use the generated `./cll` runner (it auto-activates the venv and sets up Stockfish on PATH):

```bash
# Run a .cll program (type-checks and interprets by default)
./cll sample-programs/valid/valid_04.cll

# Dump all tokens from the lexer
./cll sample-programs/valid/valid_01.cll --dump-tokens

# Dump the Abstract Syntax Tree
./cll sample-programs/valid/valid_01.cll --dump-ast

# Run only the type checker
./cll sample-programs/valid/valid_04.cll --type-check

# Explicitly request interpret mode (same as default)
./cll sample-programs/valid/valid_04.cll --run
```

Alternatively, activate the venv manually:

```bash
source .venv/bin/activate
python src/main.py sample-programs/valid/valid_04.cll
```
